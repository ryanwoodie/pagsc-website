# Hosting and DNS

## Decision: GitHub Pages

The site is static, so it can be served free from GitHub Pages with the club's own domain.

- **Custom domain and HTTPS:** supported, with a free certificate.
- **Speed:** files are served from a content delivery network; for a small static site this is as fast as hosting gets.
- **Limits:** published site up to 1 GB, a soft limit of 100 GB of traffic a month, deployments must finish in 10 minutes. This site will use a small fraction of each.
- **Cost:** nothing on a free GitHub account, provided the repository is public.

Two things to know:

1. **The repository must be public** on a free account. Nothing private goes in it (see `CLAUDE.md`). A paid GitHub plan allows a private repository.
2. **GitHub's terms say Pages is not for running an online business or e-commerce site.** A non-profit club's information site that links out to a payment page hosted elsewhere is ordinary use, and no payment details are handled on the site itself.

**Fallback:** Cloudflare Pages. It is also free, also takes a custom domain, builds from the same repository with no code changes, and allows a private repository. Switch only if either point above becomes a problem.

Sources: [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), [Managing a custom domain](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Deployment

- A GitHub Actions workflow builds with Astro and deploys with the official Pages actions on every push to `main`.
- The same workflow runs on a schedule in season to refresh "Next flying days".
- In the repository's settings, Pages source is "GitHub Actions".
- Until the domain is moved, the site is reachable at `https://<account>.github.io/<repo>/`. Build with the matching `base` path during this stage and remove it at cutover.

## Before the cutover: email

**The club has mail on the pagsc.ca domain** (the current site links to webmail). Mail is delivered according to the domain's MX records, which are separate from the website's records.

- Change only the website records listed below. Leave every MX, SPF, DKIM and mail-related record exactly as it is.
- Do not cancel the CanSpace hosting until it is confirmed whether pagsc.ca mailboxes are still used. If they are, either keep that hosting for mail or move the mailboxes first.

## How it was done (3 October 2026)

- DNS moved from CanSpace to Cloudflare (Free plan, the club's account). Nameservers at CanSpace: `dean.ns.cloudflare.com`, `laila.ns.cloudflare.com`. The domain registration stays at CanSpace.
- Website records (DNS only, not proxied): see `docs/cloudflare-pagsc.ca.zone`. GitHub Pages custom domain `www.pagsc.ca`, HTTPS enforced; `pagsc.ca` redirects to it.
- Mail: Cloudflare Email Routing, catch-all to the club Gmail. The CanSpace mailboxes and cPanel are no longer reachable by name.
- Keep the CanSpace hosting until the WordPress backup is downloaded and nothing is missed; then it can be cancelled. Keep the domain registration.

## Original cutover checklist (Ryan)

1. Confirm the new site is complete at its `github.io` address.
2. Take a full backup of the WordPress site and database from cPanel.
3. Note the current DNS records for pagsc.ca, especially MX and TXT.
4. In the repository settings, under Pages, set the custom domain to `www.pagsc.ca`. This writes a `CNAME` file; keep it in `public/`.
5. In the DNS zone for pagsc.ca:
   - `www` CNAME to `<account>.github.io`
   - Apex `A` records: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - Apex `AAAA` records: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - Remove the old apex `A` record that pointed to CanSpace, and any old `www` record.
6. Wait for the certificate, then tick "Enforce HTTPS".
7. Check: `https://www.pagsc.ca` loads, `pagsc.ca` redirects to it, every old URL in `reference/current-site-audit.md` redirects, the form submits, and mail to a pagsc.ca address still arrives.
8. Update the Google Business Profile, Facebook page and the schedule sheet's links to the new pages.

The current site keeps `www` as its address, so `www.pagsc.ca` stays the canonical host and existing links keep working.

## Redirects

GitHub Pages cannot issue server redirects. Old paths are handled by static redirect pages generated by Astro's `redirects` config (a meta refresh plus a canonical link). The mapping is in `reference/current-site-audit.md`.
